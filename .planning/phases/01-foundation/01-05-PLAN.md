<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Celery worker fork → DB connections | Forked worker must not inherit parent's asyncpg connection pool |
| Redis broker → task queue | Tasks serialized as JSON only (no pickle — reduces deserialization attack surface) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | Shared asyncpg connections across fork | mitigate | worker_process_init calls `init_worker_process()` which disposes parent engine and creates fresh engine per worker child; tested in test_worker_init.py (Plan 01) |
| T-05-02 | Tampering | Celery task serializer allows pickle | mitigate | `task_serializer = "json"` and `accept_content = ["json"]` — pickle deserialization is disabled; prevents arbitrary code execution via malicious task payloads |
| T-05-03 | Denial of Service | redbeat_lock_timeout too short — duplicate beat tasks | mitigate | `redbeat_lock_timeout = 32400` (9 hours) exceeds all expected task runtimes; prevents duplicate pipeline runs |
| T-05-04 | Tampering | Module-level DB import triggers connection before fork | mitigate | `from app.db.session import init_worker_process` is inside `_on_worker_process_init` function body — DB is never imported at module level of celery_app.py |
</threat_model>
