<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| JWT decode → claims | Tokens decoded with explicit algorithm list — prevents algorithm confusion |
| ContextVar → DB queries | Tenant ID flows from HTTP context into SQLAlchemy session — default=None prevents cross-request contamination |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing | JWT algorithm confusion | mitigate | `verify_token` calls `jwt.decode(..., algorithms=["HS256"])` — explicit list prevents "alg:none" header attack; never pass `algorithms=None` |
| T-03-02 | Spoofing | Stale JWT after logout | mitigate | Access token TTL = 15 minutes (settings.access_token_expire_minutes); refresh token rotation on every use (Plan 06 auth endpoint rotates cookie) |
| T-03-03 | Information Disclosure | PII in logs | mitigate | structlog configured with merge_contextvars only — no auto-logging of request bodies or query parameters; INFRA-06 test (Plan 01) asserts no PII in output |
| T-03-04 | Information Disclosure | python-jose CVEs | mitigate | python-jose is NOT imported; only PyJWT 2.12.1 used; `grep -r "jose" backend/app/core/security.py` must return empty |
| T-03-05 | Information Disclosure | Tenant context leakage | mitigate | `_tenant_id_var` default=None; each async task/request gets isolated context via Python's asyncio ContextVar semantics |
</threat_model>
