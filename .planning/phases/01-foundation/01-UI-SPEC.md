# Phase 1 — UI Design Contract

> Visual and interaction contract for the frontend shell scaffolded in Phase 1.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker before executor consumes.
>
> Scope: login page, sidebar shell, topbar, 8 placeholder pages.
> Not in scope: charts, data tables, dashboard widgets (Phase 7).

| Property | Value |

## Spacing Scale

Declared values (multiples of 4 only). These map to Tailwind v4 spacing utilities.

| Token | Value | Tailwind class | Usage |
|-------|-------|----------------|-------|
| xs | 4px | p-1 / gap-1 | Icon gaps, badge padding, inline element spacing |
| sm | 8px | p-2 / gap-2 | Compact element spacing, nav item icon-to-label gap |
| md | 16px | p-4 / gap-4 | Default content padding, form field gaps |
| lg | 24px | p-6 / gap-6 | Section padding, card padding |
| xl | 32px | p-8 / gap-8 | Layout gaps, major content blocks |
| 2xl | 48px | p-12 | Major section breaks |
| 3xl | 64px | p-16 | Page-level vertical rhythm |

Exceptions:
- Sidebar nav items: 44px minimum touch target height (accessibility — WCAG 2.5.5). Achieved via `py-[12px] px-3` (12px top + 12px bottom + 20px icon height = 44px).
- Sidebar width: 240px fixed (not a spacing token — structural dimension).
- Topbar height: 56px fixed (not a spacing token — structural dimension).

## Typography

Font: **Inter** via `@import` in globals.css (or Next.js `next/font/google`).

| Role | Size | Weight | Line Height | Tailwind | Usage |
|------|------|--------|-------------|---------|-------|
| Body | 14px | 400 (regular) | 1.5 | `text-sm` | Nav labels, form labels, table content, placeholder paragraph text |
| Label | 12px | 400 (regular) | 1.4 | `text-xs` | Badges, section subheadings, meta text |
| Heading | 20px | 600 (semibold) | 1.2 | `text-xl font-semibold` | Page headings ("În curând"), card titles |
| Display | 28px | 600 (semibold) | 1.1 | `text-3xl font-semibold` | Login page headline only |

## Color

Mode: **Light mode only** in Phase 1. Dark mode is Phase 9 scope (deferred).

shadcn CSS variable names used; Tailwind v4 maps them via `@theme`.

| Role | HSL Value | Hex Approx | Usage |
|------|-----------|-----------|-------|
| Dominant (60%) | `hsl(0 0% 100%)` | `#FFFFFF` | Page background, main content area |
| Secondary (30%) | `hsl(240 5% 96%)` | `#F4F4F6` | Sidebar background, topbar background, card surfaces |
| Accent (10%) | `hsl(221 83% 53%)` | `#2563EB` | Active nav item indicator, login button, focused form ring |
| Accent foreground | `hsl(0 0% 100%)` | `#FFFFFF` | Text on accent backgrounds |
| Destructive | `hsl(0 72% 51%)` | `#DC2626` | Not used in Phase 1 (no destructive actions); reserved token |
| Border | `hsl(240 6% 90%)` | `#E4E4E7` | Sidebar/topbar dividers, form field borders |
| Muted text | `hsl(240 4% 46%)` | `#71717A` | Placeholder text, "În curând" subtitle, nav labels (inactive) |
| Foreground | `hsl(240 10% 4%)` | `#09090B` | Primary body text, active nav labels |

Accent (`#2563EB`) is reserved for:
1. Active navigation item left border indicator (3px solid, `rounded-sm`)
2. Active navigation item text and icon color
3. Login form submit button (`Intră în cont`) — background fill
4. Login form submit button hover state — slightly darker (`hsl(221 83% 45%)`)
5. Input focus ring (2px outline via shadcn ring token)

Accent is NOT used for: passive hover states, decorative elements, or general interactive feedback.

Hover state for nav items (inactive): `hsl(240 5% 92%)` — one step darker than secondary, no accent.

## Interaction Contracts

### Route Transitions

- Route change: no loading animation in Phase 1. Next.js App Router handles navigation natively.
- Active nav item: updates synchronously on `usePathname()` change — no delay.
- Protected route access without token: proxy.ts redirects to `/login` before any page renders (no flash of protected content).

### Auth Flow

```
POST /api/v1/auth/login
  → success: store access_token in non-HttpOnly cookie (JavaScript writes it after JSON response);
             refresh_token set as HttpOnly cookie by backend
  → navigate to `/` (Overview placeholder)
  → failure: display inline auth error banner (see Copywriting Contract)

Interceptor (TanStack Query / fetch wrapper):
  → 401 received: call POST /api/v1/auth/refresh (refresh_token cookie sent automatically)
  → success: retry original request with new access_token
  → failure: clear access_token cookie, redirect to /login

proxy.ts:
  → reads `access_token` cookie
  → verifies with jose.jwtVerify
  → invalid/missing: redirect to /login
  → valid: pass through + set next-intl locale headers
```

### Loading States

Phase 1 has no data fetching. Login form uses local `isSubmitting` state from react-hook-form.
No skeleton loaders, no suspense boundaries needed in Phase 1. (Those are Phase 7 contracts.)

### Form Interaction

Login form:
- Validation: on submit only (not on blur). Errors clear on next keystroke.
- Submit: button disabled + spinner while `isSubmitting = true`
- Enter key submits the form (standard browser behavior, no custom handler needed)
- Tab order: email → password → submit button (DOM order)

### Locale Toggle

Phase 1: implement a locale toggle stub in the topbar.
- Simple `<Button variant="ghost" size="sm">` showing current locale ("RO" or "EN")
- On click: calls `useRouter().push()` with `{locale: 'en'}` via next-intl `useRouter`
- No locale picker dropdown — just a toggle button switching RO ↔ EN
- State: drives from URL via next-intl routing (locale stored in cookie by next-intl, not Zustand)
