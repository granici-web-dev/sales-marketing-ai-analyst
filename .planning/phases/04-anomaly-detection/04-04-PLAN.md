<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Celery task←broker | Task arguments (tenant_id) arrive as JSON from Redis — validated as UUID at entry point |
| Task→DB writes | SyncRun and DetectedProblem writes use SQLAlchemy ORM — no raw string interpolation |
| Pipeline chain | Celery chain passes immutable signatures (.si()) — no result data passed between tasks |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04-01 | Spoofing | detect_anomalies task tenant_id arg | mitigate | UUID(tenant_id) at task entry — malformed strings raise ValueError, which autoretry catches and fails the run; no unscoped DB access |
| T-04-04-02 | Tampering | celery_app JSON serialization | mitigate | task_serializer="json", accept_content=["json"] — pickle disabled, prevents arbitrary code execution via malicious payloads (T-05-02 from Phase 1) |
| T-04-04-03 | Repudiation | SyncRun audit trail | mitigate | Every detect_anomalies run writes SyncRun(source="anomaly") with started_at, completed_at, records_synced, error_msg; stale runs cleaned up (WR-06) |
| T-04-04-04 | Information Disclosure | error_msg in SyncRun | mitigate | str(exc)[:500] captures error for ops debugging; exception messages never contain customer PII (service layer logs only counts/dates) |
| T-04-04-05 | Denial of Service | NullPool + engine dispose | mitigate | NullPool ensures no connection leaks on task retry; finally: await task_engine.dispose() runs on both success and failure paths |
| T-04-04-06 | Elevation of Privilege | daily_pipeline chain extension | accept | detect_anomalies.si() is immutable signature — cannot inject arguments or modify preceding task results; chain failure halts pipeline per PIPE-02 |
| T-04-04-SC | Tampering | No new package installs in Wave 4 | accept | No new dependencies; all celery/sqlalchemy/structlog packages already in pyproject.toml |
</threat_model>
