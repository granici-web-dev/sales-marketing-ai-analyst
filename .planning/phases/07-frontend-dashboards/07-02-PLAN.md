## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL params → API call | ?from= and ?to= values from useSearchParams fed directly to apiClient.get URL |
| API response → chart data | Revenue strings from backend parsed via parseFloat before Recharts consumption |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-7-01 | Tampering | useSalesDashboard queryFn URL | mitigate | from/to are strings from useSearchParams; validate with new Date(param) + isNaN check before use — invalid values fall back to getDefaultDateRange() per D-10 |
| T-7-02 | Tampering | date-range-picker.tsx router.push | mitigate | Only YYYY-MM-DD format strings pushed to URL via format(date, "yyyy-MM-dd"); DayPicker returns Date objects, not raw strings |
| T-7-03 | Tampering | All chart components | mitigate | Never use dangerouslySetInnerHTML; all API strings rendered as JSX text nodes (auto-escaped by React) |
| T-7-04 | Spoofing | apiClient.get in useSalesDashboard | accept | credentials: "include" inherited from apiClient; SameSite=Lax cookie set by Phase 1 backend handles CSRF |
| T-7-05 | Info Disclosure | revenue/source data in chart | accept | Data is business analytics visible to authenticated users only; auth enforced by apiClient 401 interceptor |
| T-7-SC | Tampering | npx shadcn add popover/tooltip (if needed) | mitigate | Official shadcn registry — no third-party registry; same legitimacy as card/skeleton already installed in Plan 01 |
</threat_model>
