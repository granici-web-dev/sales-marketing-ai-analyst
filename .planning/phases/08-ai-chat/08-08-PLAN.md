<objective>
Close three BLOCKERs that share the chat streaming-handler / orchestrator surface, plus one folded-in WR:

- **CR-02** — Rate-limit counter is INCR'd BEFORE stream-lock SET NX in `backend/app/api/v1/chat.py:305-333`. A 409 conflict from a double-tap permanently burns one of the 30 hourly tokens. A user with a flaky connection locks themselves out after ~30 accidental retries.
- **CR-03** — `backend/app/services/chat/orchestrator.py:412-428` schedules `asyncio.create_task` whose closure captures `self._session` and calls `self._session.commit()` ~3s later (Haiku timeout), but FastAPI's `get_session` dependency has already closed the AsyncSession by then. Every production title persistence silently fails. The bare `except Exception: pass` at line 420 hides the failure.
- **CR-05** — `backend/app/services/chat/orchestrator.py:285-322 + 367-386` never commits between `insert_tool_call` (multiple per turn) and `insert_assistant_message`. If the assistant insert fails, the session is left in error state and every `chat_tool_calls` audit row written for the turn is rolled back. D-21 contract ("every tool call writes exactly one row") is structurally violated on the failure path that needs it most. The user message ALSO gets rolled back, even though `conversation_meta` already advertised its UUID to the frontend.
- **WR-10** — Folded into CR-03: replace bare `except Exception: pass` at orchestrator.py:419-421 with `self._log.warning("chat.title.commit_failed", error=str(exc)[:200])`.
