## Spacing Scale

Declared values (multiples of 4, aligned with Tailwind v4 default spacing):

| Token | Value | Usage in Chat |
|-------|-------|---------------|
| xs    | 4px   | Tool pill internal icon-text gap; thinking-dot inter-dot gap |
| sm    | 8px   | Inter-pill gap; chip gap; bubble internal padding-y |
| md    | 16px  | MessageBubble internal padding; ChatInput internal padding; gap between messages in MessageList |
| lg    | 24px  | Sidebar list-item gap; section spacing inside ConversationsList header; gap between SuggestedQuestions row and ChatInput |
| xl    | 32px  | Page horizontal padding on desktop (`md:px-8`); centered welcome card padding-y |
| 2xl   | 48px  | Empty-state vertical breathing room above welcome card on mobile |
| 3xl   | 64px  | Top spacing for centered welcome card on desktop (vertical center is the actual layout but 64px is the minimum gap from top before vertical centering kicks in) |

Exceptions:
- **Touch targets ≥ 44px (mobile NON-NEGOTIABLE per Phase 7 D-17 carry-forward).** Send button, conversation list items, suggested-question chips, sidebar nav items, archive trigger — all `min-h-[44px]`.
- **Sidebar width:** 260px desktop fixed (per D-13 + SPEC.md §13.8) — not a multiple of 4 in token sense, but matches the spec verbatim.
- **Bubble max-width:** 75% of message column on desktop (`md:max-w-[75%]`), 90% on mobile (`max-w-[90%]`) — proportional, not pixel-token.
- **Auto-scroll threshold:** 100px from bottom (D-34) — interaction constant, not a layout token.

## Typography

Three sizes, two weights. Aligned with Phase 7 `text-sm` body baseline so dashboard-to-chat reads
consistently.

| Role | Size | Weight | Line Height | Tailwind class | Usage |
|------|------|--------|-------------|----------------|-------|
| Body | 14px | 400 (regular) | 1.5 (`leading-relaxed` ≈ 1.625; we use Tailwind default `leading-normal` = 1.5) | `text-sm` | Message bubble text, conversation list titles, input textarea, tool pill labels, sidebar nav, markdown paragraphs |
| Label | 12px | 400 (regular) | 1.4 | `text-xs` | Conversation timestamp, tool pill secondary hint (`· 30 zile`), source-trace footer, sidebar "Conversații recente" header, error messages |
| Heading | 18px | 600 (semibold) | 1.3 (`leading-snug`) | `text-lg font-semibold` | Welcome card H1, conversation header in ChatMain on desktop, modal/sheet titles |
| Display | 24px | 600 (semibold) | 1.2 | `text-2xl font-semibold` | Empty-state welcome H1 ("Bună! Întreabă-mă despre datele tale.") on desktop, scaled to `text-xl` (20px) on mobile |

Weight rule: **only `400` (regular) and `600` (semibold)** in the chat surface. No `font-bold`,
no `font-medium`. Markdown `<strong>` (KPI bolding) renders at `font-semibold` not `font-bold`.

## Color

Inherits the global palette from `frontend/src/app/globals.css` (Tailwind v4 `@theme` block).
60/30/10 split is enforced — accent is reserved, not freely sprinkled.

| Role | Value | Token | Usage |
|------|-------|-------|-------|
| Dominant (60%) | `hsl(0 0% 100%)` (white) | `--color-background` / `bg-background` | Page background, ChatMain background, MessageBubble (assistant) background, ChatInput background, welcome card background |
| Secondary (30%) | `hsl(240 5% 96%)` (zinc-50-ish) | `--color-secondary` / `bg-secondary` | ConversationsList sidebar background (matches existing app sidebar), MessageBubble (user) background, ToolPill background, SuggestedQuestion chip background (idle), sidebar item hover state |
| Accent (10%) | `hsl(221 83% 53%)` (blue-600) | `--color-accent` / `bg-accent` + `text-accent` | **RESERVED FOR — strict list below.** |
| Destructive | `hsl(0 72% 51%)` (red-600) | `--color-destructive` / `text-destructive` + `bg-destructive` | Archive (soft-delete) confirmation button; hallucination-guard fallback error banner border-left; SSE `error` event toast border; "Nu pot da un răspuns precis" inline alert text |
| Muted foreground | `hsl(240 4% 46%)` | `--color-muted-foreground` / `text-muted-foreground` | Timestamps, tool pill secondary hint, "Verific cifrele..." indicator text, collapsed tool-pill summary line, source-trace footer |
| Border | `hsl(240 6% 90%)` | `--color-border` / `border` | All component borders, sheet boundary, input border, message bubble separators (none — we use background contrast, not borders) |

### Accent reserved-for list (strict — never grow this list without UI-SPEC revision):

1. **Send button background** (primary CTA) — `bg-accent text-accent-foreground`
2. **"Conversație nouă" (New conversation) button** (primary CTA in sidebar) — `bg-accent text-accent-foreground`
3. **Active conversation item** in sidebar — `bg-accent/10 text-accent border-l-[3px] border-accent` (matches existing sidebar active-state pattern from Phase 1 sidebar.tsx, just substituting global token)
4. **Markdown `<strong>` KPI bolding** — `font-semibold text-accent` (e.g. **285.000 RON**)
5. **Dashboard link pills** (`[Sales Dashboard](/sales)` rendered) — `bg-accent/10 text-accent rounded-md inline-flex items-center gap-1 px-2 py-0.5` with `ChevronRight` icon at `text-accent`
6. **Suggested-question chip hover state** — border becomes `border-accent` and text becomes `text-accent` (idle state stays secondary)
7. **Focus ring** on textarea + buttons — `focus-visible:ring-2 focus-visible:ring-accent` (uses `--color-ring` which is the same blue)
8. **Auto-scroll "↓ Mesaje noi" floating button** — `bg-accent text-accent-foreground rounded-full shadow-md`

Anything else stays in the dominant/secondary/muted palette. Tool pills are NOT accent — they're
`bg-secondary text-foreground` with a `text-muted-foreground` secondary hint, deliberately quiet
so they don't fight with the actual answer text.

### Destructive action: archive conversation

- **Trigger:** kebab menu (`MoreVertical` icon button) on each conversation list item; on the active conversation, also in the ChatMain header.
- **Confirmation:** shadcn `AlertDialog` (to be added via radix umbrella pattern — `@radix-ui/react-alert-dialog` is included in the `radix-ui` umbrella v1.4.3, so no new package install needed).
- **Confirm button styling:** `variant="destructive"` (red).
- **No undo, no toast** (MVP1) — soft-archive means the user can recover via `?archived=true` URL per D-15.

## Tool Pill Content Rules

Each of the 12 tools (D-02) gets a lucide-react icon and a 1-2 word humanized hint derived from
`input` payload. Format: `<Icon size={14}/> {tool_name} · {hint}`.

| Tool name (passed to Claude) | Icon (lucide-react) | Hint formula | Example rendered |
|------------------------------|---------------------|--------------|------------------|
| `get_kpi` | `Calculator` | day-count between `date_from` and `date_to`: `{N} zile` (Romanian plural per i18n) | `🧮 get_kpi · 30 zile` |
| `get_funnel_data` | `Filter` | day-count: `{N} zile` | `🔽 get_funnel_data · 30 zile` |
| `get_salesperson_performance` | `Users` | `{N} zile` + optional ` · {salesperson_first_name}` if `salesperson_id` provided | `👥 get_salesperson_performance · 30 zile` |
| `get_leads` | `List` | filter summary: `{lifecycle ?? "toți"}, {N} max` | `📋 get_leads · activi, 50 max` |
| `compare_periods` | `GitCompare` | `{period_a label} vs {period_b label}` (e.g. `30 zile vs 30 zile`) | `⇆ compare_periods · 30 zile vs 30 zile` |
| `get_loss_reasons` | `TrendingDown` | day-count: `{N} zile` | `📉 get_loss_reasons · 30 zile` |
| `get_lead_categories_breakdown` | `PieChart` | day-count: `{N} zile` | `🥧 get_lead_categories_breakdown · 30 zile` |
| `get_showroom_performance` | `Store` | `{showroom ?? "toate showroom-urile"}, {N} zile` | `🏬 get_showroom_performance · toate showroom-urile, 30 zile` |
| `get_recent_insight` | `Lightbulb` | `{date or "azi"}` | `💡 get_recent_insight · azi` |
| `explain_metric` | `BookOpen` | `{metric_name}` (uppercase, e.g. `CAC`) | `📖 explain_metric · CAC` |
| `get_stuck_leads` | `Hourglass` | `{days}+ zile` (e.g. `14+ zile`) | `⏳ get_stuck_leads · 14+ zile` |
| `get_trend` | `LineChart` | `{metric_name} · {period_days} zile` | `📈 get_trend · revenue · 90 zile` |

## Markdown Rendering Rules

### Allowed elements (whitelist enforced via `react-markdown` `allowedElements` prop)

```ts
allowedElements: [
  "p",
  "strong",
  "em",
  "ul",
  "ol",
  "li",
  "a",
  "code",
  "table",
  "thead",
  "tbody",
  "tr",
  "th",
  "td",
  "br",
]
```

**Disallowed (silently dropped):** `script`, `style`, `iframe`, `img`, `video`, `object`, `svg`, headings (`h1`-`h6`), raw HTML. No `unwrapDisallowed` — disallowed elements and their children are removed entirely. XSS hardening.

### Custom renderers

| Element | Renderer | Output |
|---------|----------|--------|
| `<p>` | Default + `className="text-sm leading-normal mb-2 last:mb-0"` | Standard paragraph spacing |
| `<strong>` | Custom: `<strong className="font-semibold text-accent">{children}</strong>` | KPI bolding per D-19 + specifics block |
| `<em>` | Default + `className="italic"` | (rarely used by Claude; supported for completeness) |
| `<ul>` / `<ol>` | Default + `className="list-disc list-inside ml-4 space-y-1 mb-2"` for `ul`; `list-decimal` for `ol` | Bulleted/numbered action lists |
| `<li>` | Default + `className="text-sm"` | List item |
| `<a>` | **Dashboard link pill mapper** — see below | Pill or external link or plain text |
| `<code>` | Default + `className="font-mono text-xs bg-secondary px-1 py-0.5 rounded"` | Inline code (used rarely — Claude may quote tool names) |

### Dashboard link pill mapper (D-18 + D-18a)

```ts
// Whitelist of allowed internal link targets:
const DASHBOARD_PATHS = new Set([
  "/sales",
  "/salespeople",
  "/marketing",
  "/insights",
  "/chat",
]);

// Render rules:
function renderLink({ href, children }) {
  if (href === "#") {
    // Bare anchor: render as plain inline text (no link).
    return <span>{children}</span>;
  }
  if (DASHBOARD_PATHS.has(href)) {
    return <DashboardLinkPill href={href}>{children}</DashboardLinkPill>;
  }
  // Any other href: render as plain text (NOT a link). Guard rejects this on server side
  // before it ever reaches the user, but defense-in-depth on the client.
  return <span className="text-muted-foreground italic">{children}</span>;
}
```

`<DashboardLinkPill>` markup:

```tsx
<Link
  href={href}
  className="inline-flex items-center gap-1 bg-accent/10 text-accent rounded-md px-2 py-0.5 text-sm hover:bg-accent/20 transition-colors"
>
  {children}
  <ChevronRight size={14} aria-hidden="true" />
</Link>
```

## Interaction Contracts

### Sending a message

1. User types in textarea. Enter sends. Shift+Enter inserts newline. `Cmd/Ctrl+Enter` also sends (power-user shortcut, no visual UI).
2. On submit:
   a. If no active conversation: `POST /chat/conversations` with `initial_message` to create + persist user message.
   b. If active conversation: skip create step.
   c. `POST /chat/conversations/{id}/messages` opens SSE stream.
3. Optimistic UI (D-33): user message appears in MessageList immediately with `status: "pending"`. Assistant bubble appears immediately too, empty, with `<ThinkingIndicator>` inside.
4. On SSE `conversation_meta` event: swap optimistic message IDs → real DB IDs (no visible change, internal state only).
5. On SSE `tool_use` event: append a new ToolPill (state `running`) inside the assistant bubble, above any text content.
6. On SSE `tool_result` event: update the matching ToolPill (state `done` or `error`). Other pills stay as-is.
7. On SSE `assistant_chunk` events: append text into the assistant bubble's MarkdownRenderer. ThinkingIndicator disappears on first chunk.
8. On SSE `regenerate_notice` event: discard the current assistant bubble's text content (keep the bubble shell + pills); show `<ThinkingIndicator state="verifying-numbers">` with `Verific cifrele...` label; continue receiving `assistant_chunk` events into the same bubble.
9. On SSE `done` event: stop the ThinkingIndicator; collapse the ToolPillsRow to summary line; mark assistant bubble complete; re-enable the input.
10. On SSE `error` event: show inline error message inside the bubble in Romanian; preserve any tokens streamed so far; re-enable the input.

### Send button disabled-while-streaming (D-11)

- `isStreaming === true` (controlled by `useChat` hook): Send button is `disabled`, tooltip on hover shows `Așteaptă răspunsul...`. Textarea remains editable (user can prep their next question).
- 409 Conflict from server (concurrent stream attempt): show inline toast under input with rate-limit-style copy. Should not happen via UI (button is disabled) but defensive case.

### Auto-scroll behavior (D-34)

- Track `scrollTop` of MessageList. Compute `distanceFromBottom = scrollHeight - scrollTop - clientHeight`.
- If `distanceFromBottom < 100px`: auto-scroll to bottom on every `assistant_chunk`.
- Else: do NOT auto-scroll; show floating `↓ Mesaje noi` button bottom-right of MessageList. Click → smooth scroll to bottom + hide button.
- When user manually scrolls back to bottom (within 100px), auto-scroll resumes.

### Suggested-question chip click (D-17)

- Click inserts text into the textarea. Textarea focuses. Text is NOT auto-sent — user can edit then press Enter.
- Chips remain visible until first user message is sent in this conversation (then chip row hides).
- Empty-conversation state (new conversation, no messages yet): chips visible above input, no welcome card.
- Zero-conversations state (user has never used chat): centered WelcomeCard with chips inside the card.

### Switching conversations

- Click `ConversationItem` → URL updates to `?conversation_id={uuid}` (using `router.push` from `next/navigation`, shallow).
- ChatMain reads `useSearchParams()`, fetches `GET /chat/conversations/{id}`, renders messages.
- On mobile: opening a conversation auto-closes the sheet (D-36).
- If currently streaming a different conversation: do NOT cancel the active stream (D-11 server enforces one stream per conversation), but the user navigates away — the stream continues server-side and persists; the UI shows the new conversation. On returning to the original, the completed message is visible (after refetch).

### Archive (soft delete) flow

- Kebab menu → "Arhivează conversația" → `AlertDialog` confirmation.
- Confirm → `DELETE /chat/conversations/{id}` → TanStack Query invalidates conversation list → if archived conversation was active, navigate to `/chat` (no conversation selected) → WelcomeCard appears (if no other conversations) or first conversation auto-loads.
- No toast confirmation (MVP1 keeps surface lean).

### Keyboard shortcuts

| Key | Action |
|-----|--------|
| `Enter` (in textarea) | Send message |
| `Shift+Enter` (in textarea) | Insert newline |
| `Cmd/Ctrl+Enter` (in textarea) | Send message (alternate) |
| `Esc` (sheet open, mobile) | Close sheet |
| `Esc` (input focused, has draft) | Clear textarea |
| `Tab` | Focus order: skip-link → New conversation → ConversationItem(s) → ChatHeader kebab → MessageList (focusable for screen readers) → SuggestedQuestions chips → Textarea → Send button |

### Loading first token target (CHAT-09)

- "First token within 2s" is a backend SLA, not a frontend interaction. Frontend only cares that the ThinkingIndicator shows from optimistic-message-render until the first `assistant_chunk` event.
- If 8s passes with no chunk: still show ThinkingIndicator (no timeout UI in MVP1; the server `error` event handles real failures).

## Accessibility

### Focus management

- Tab order matches visual order (see Interaction Contracts).
- On mobile, opening the conversation Sheet traps focus inside the sheet until closed (radix `Sheet` handles this).
- Sending a message keeps focus on the textarea (so user can immediately type their next question).
- Opening the archive AlertDialog moves focus to the Cancel button by default (safer; matches shadcn convention).

### Live regions

- `MessageList` has `role="log" aria-live="polite" aria-atomic="false"` so screen readers announce new messages as they complete (not while streaming token-by-token, which would be noisy).
- `ThinkingIndicator` is wrapped in `<span role="status" aria-live="polite">` so SR announces "Se gândește" / "Verific cifrele" / "Caut datele".
- `ToolPill` state changes are NOT individually announced (would be noisy). Only the collapsed summary `🔧 {n} unelte folosite` is announced via the bubble-level live region when the bubble completes.

### Color contrast

All copy uses tokens that satisfy WCAG AA (4.5:1 for body text, 3:1 for large):

- `text-foreground` (#0a0a0b ≈ hsl 240 10% 4%) on `bg-background` (#ffffff): 19.5:1 ✓ AAA
- `text-muted-foreground` (#737378 ≈ hsl 240 4% 46%) on `bg-background`: 4.97:1 ✓ AA
- `text-accent` (#2563eb ≈ hsl 221 83% 53%) on `bg-background`: 4.83:1 ✓ AA
- `text-accent-foreground` (#ffffff) on `bg-accent` (#2563eb): 4.83:1 ✓ AA
- `text-destructive` (#dc2626 ≈ hsl 0 72% 51%) on `bg-background`: 4.55:1 ✓ AA

- Every interactive element reachable via Tab.
