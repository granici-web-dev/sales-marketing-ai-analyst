## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Celery task → Redis | Lock key `sync:mefi:{tenant_id}` — must use tenant_id to prevent cross-tenant lock collision |
| MefiRepository → PostgreSQL | Core-level INSERT bypasses ORM tenant filter — explicit tenant_id in every row dict is the only protection |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-08 | Information Disclosure | bulk_upsert_leads row dicts | mitigate | MefiRepository validates tenant_id present in every row dict (ValueError if absent); Pitfall 5 |
| T-02-09 | Tampering | Redis lock key | mitigate | Lock key includes tenant_id — prevents one tenant's lock from blocking another |
| T-02-10 | DoS | Celery chain halts on ETL failure | accept | PIPE-02 design intent — ETL failure stops metrics/anomaly/insights from running on stale data |
| T-02-11 | Spoofing | tenant_id passed as string to Celery task | mitigate | UUID(tenant_id) conversion at task entry raises ValueError on malformed input |
